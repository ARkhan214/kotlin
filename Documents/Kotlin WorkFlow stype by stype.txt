অ্যান্ড্রয়েড বা কোটলিন প্রজেক্টে ডেটা সেভ করার প্রসেসটা স্প্রিং বুটের মতোই লজিক্যাল, কিন্তু এখানে আপনাকে "Client-Side Perspective" থেকে চিন্তা করতে হবে। স্প্রিং বুটে আপনি API তৈরি করেন, আর অ্যান্ড্রয়েডে আপনি সেই API-কে Consuming (ব্যবহার) করেন।

নিচে একটি ইউজার সেভ করার কমপ্লিট অ্যান্ড্রয়েড ওয়ার্কফ্লো এবং ফাইলগুলোর কাজের ক্রম দেওয়া হলো:

---

###  Android API Post Request Workflow (Step-by-Step)

ধরা যাক, আপনার কাছে একটি এপিআই আছে: `POST /api/users/save`

#### ১. Data Class (The Entity)

স্প্রিং বুটের `Entity`-র মতো এখানে আমরা তৈরি করি ডেটা ক্লাস। এটি সার্ভারে পাঠানো ডেটার ফরম্যাট ঠিক করে।

```kotlin
data class UserRequest(
    val name: String,
    val email: String
)

```

#### ২. Retrofit Interface (The Endpoint Definition)

স্প্রিং বুটে যেমন `@RestController`-এ এন্ডপয়েন্ট লিখতেন, এখানে তার উল্টো। আমরা বলি কোন এন্ডপয়েন্টে ডেটা যাবে।

```kotlin
interface ApiService {
    @POST("users/save")
    suspend fun saveUser(@Body user: UserRequest): Response<UserResponse>
}

```

#### ৩. Repository (The Data Coordinator)

রিপোজিটরির কাজ হলো ViewModel-কে ডেটা এনে দেওয়া। এটি `ApiService` কল করে।

```kotlin
class UserRepository(private val apiService: ApiService) {
    suspend fun addUser(user: UserRequest) = apiService.saveUser(user)
}

```

#### ৪. ViewModel (The Logic Holder)

স্প্রিং বুটের `Service` লেয়ারের মতো কাজ করে। এটি UI থ্রেডকে ব্লক না করে ব্যাকগ্রাউন্ডে (Coroutines ব্যবহার করে) এপিআই কল চালায়।

```kotlin
class UserViewModel(private val repository: UserRepository) : ViewModel() {
    fun saveUserToApi(user: UserRequest) {
        viewModelScope.launch {
            val response = repository.addUser(user)
            if(response.isSuccessful) {
                // সফল হলে UI-কে জানাবে
            }
        }
    }
}

```

#### ৫. UI / Activity (The Controller/View)

ইউজার যখন বাটনে ক্লিক করবে, তখন এখান থেকে কাজ শুরু হয়।

```kotlin
saveButton.setOnClickListener {
    val user = UserRequest("Zakir", "zakir@example.com")
    viewModel.saveUserToApi(user)
}

```

### কাজের ক্রম (Execution Order)

একটি ডেটা সেভ করার সময় ফাইলগুলো নিচের ক্রমানুসারে কাজ করে:

1. Activity/Fragment: ইউজার বাটনে ক্লিক করে ডেটা ইনপুট দেয়। এখান থেকে ViewModel-এর ফাংশন কল হয়।
2. ViewModel: এটি একটি Coroutine Scope তৈরি করে যাতে অ্যাপ হ্যাং না হয় এবং Repository-কে কল দেয়।
3. Repository: এটি নেটওয়ার্ক বা লোকাল ডাটাবেসের সাথে কানেকশন হ্যান্ডেল করে এবং Retrofit/ApiService কল করে।
4. Retrofit/Network: এটি ইন্টারনেটের মাধ্যমে আপনার স্প্রিং বুট ব্যাকেন্ডে JSON ডেটা পাঠিয়ে দেয়।
5. Response Handling: ব্যাকেন্ড থেকে রেসপন্স আসলে সেটি আবার উল্টো পথে (Repository -> ViewModel -> UI) ফিরে আসে এবং স্ক্রিনে "Success" মেসেজ দেখায়।

### 🛠️ স্প্রিং বুট বনাম অ্যান্ড্রয়েড (সহজ তুলনা)

| ফিচার | স্প্রিং বুট (Backend) | কোটলিন অ্যান্ড্রয়েড (Frontend) |
| --- | --- | --- |
| Data Structure | `@Entity` | `Data Class` |
| Interface | `JpaRepository` | `Retrofit Interface` |
| Logic Layer | `@Service` | `ViewModel` |
| API Handling | `@RestController` (API তৈরি) | `Retrofit` (API কল করা) |
| Dependency Injection | `@Autowired` | `Hilt` / `Koin` (`@Inject`) |
